## 01 基础排版与文字

全文首个 `#` 一级标题在推送时自动剥除，仅用作公众号文章主标题；画布固定白底 `#ffffff`，默认字体栈为无衬线系统黑体。正文使用 `16px`，行高 `1.7`，段距 `0.72em`，字距 `0.01em`，主墨色 `#111819`。**中文边界加粗**直接写 `**文字**`（支持嵌套行内代码），字重 `700`。行内代码写法为 `` `code` ``，字号 `0.88em`，浅灰底 `#e8eeee`，圆角 `3px`。

### 三级小节标题

三级标题原文写法为 `### 标题`，字号 `17px` 粗体，行高 `1.4`，左侧 `3px` 墨色 `#111819` 竖线，左内边距 `10px`，上边距 `20px`、下边距 `8px`。

- 无序列表原文写法为 `- 项目`，左缩进 `1.4em`，条目间距 `0.25em`。
- 列表字色统一为 `#111819`。

1. 有序列表原文写法为 `1. 项目`。
2. 与无序列表保持相同缩进与行距。

## 02 提示块、引文与代码

> TIP 提示块
>
> 浅底 `#f5f7f7`，左 `3px` 墨青 `#007275` 竖线，标签 `10px`，标题 `15px` 粗体，正文 `14px` 行高 `1.68`，上下外边距 `16px`。原文写法：`> TIP 标题` 或 `:::tip[标题]`。

> NOTE 注释块
>
> 浅底 `#f5f7f7`，左 `3px` 次要灰 `#5d6667` 竖线，正文 `14px`。原文写法：`> NOTE 标题` 或 `:::note[标题]`。

> WARNING 警告块
>
> 浅红底 `#f7f5f5`，左 `3px` 警告红 `#a91611` 竖线，正文 `14px`。原文写法：`> WARNING 标题` 或 `:::warning[标题]`。

> IMPORTANT 重要块
>
> 浅底 `#f5f7f7`，左 `3px` 墨色 `#111819` 竖线，正文 `14px`。原文写法：`> IMPORTANT 标题` 或 `:::important[标题]`。

> 普通引用不加边框和底色，按 `16px` 正文段落输出。原文写法：`> 普通段落`。

> 长引使用衬线体 `16px`，行高 `1.68`，左侧 `2px` 墨色 `#111819` 竖线，上下紧凑留白 `14px`；末行 `——` 开头为 `12px` 右对齐出处（颜色 `#5d6667`）。
>
> —— 原文写法：`> 引文` 末行加 `> —— 出处`

```bash
# 代码块：浅底 #f5f7f7，左 3px 灰竖线 #5d6667，代码 14px，行高 1.7，上下边距 16px，语言名 10px 大写角标
node scripts/wechat.mjs push templates/editorial.md
```

# 一级标题（后续篇章分隔）

非首个 `#` 一级标题放在篇章分隔处，字号 `22px` 粗体，行高 `1.3`，底部 `1px` 墨色 `#111819` 实线收住。

## 04 编辑部风 2.0 杂志组件（数据卡、档案卡、对照卡与清单）

::: metrics[数据指标卡（2–3 栏等宽表格）]
91% | 核心指标一 | 补充数据说明
2–4 条 | 核心指标二 | 手机端稳固不崩
60–69% | 核心指标三 | 微信全端兼容
:::

::: dossier[移动优先档案卡（替代手机端宽表格）]
条目名称 A | 标签胶囊
字段一：用「字段名：说明」结构化呈现，告别手机端多列竖条表格。
字段二：不同卡片之间用单独一行 `---` 分隔。
---
条目名称 B | 标签胶囊
字段一：每张卡自动生成 `01`、`02` 墨青索引编号。
:::

::: versus[双轨对照卡（如 ToB vs ToC）]
方案 A 标题 | 轨道 A
要点一：墨青标头，清晰区分第一条路线。
---
方案 B 标题 | 轨道 B
要点一：墨黑标头，直观对照第二条路线。
:::

::: checklist[行动底牌清单]
01. 第一条行动项：带编号方标与层次化说明，适合文末收藏与转发。
02. 第二条行动项：同样支持 `**加粗**` 与行内代码。
:::

::: steps[流程步骤 / 阶梯组件（steps）]
第一步：定位问题 | 诊断阶段 | 支持单行 `标题 | 标签 | 说明` 或 `---` 分隔的多行块
---
第二步：警惕风险 | 避坑提示
要点：当标题或标签包含「警告 / 坑 / 避开 / 风险 / 阴影」时，自动切换为红色警示态。
:::

::: verdict[金句判词 / 核心结论卡（verdict）]
真正决定传播率的，不是堆砌多少信息，而是读者一眼就能带走那句最硬的判断。
副文本：可选补充说明行，适合放在章节转折或核心观点收口处。
:::

::: qa[核心拷问 / 问答卡组（qa）]
Q：为什么公众号版必须用双栏表格替代 CSS Grid 或 Flex？
A：微信客户端会清洗部分现代布局属性，纯表格双栏在 iOS、Android 和桌面端微信中 100% 对齐不塌陷。
---
Q：多个问答之间如何分隔？
A：用单独一行 `---` 分隔即可，编号会自动从 `Q01` 递增。
:::
